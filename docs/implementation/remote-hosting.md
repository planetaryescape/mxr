## Released clients must fail safely during an upgrade

The original baseline used IPC 12. v0.6.226 uses IPC 31 and schema 110; clients still require exact remote IPC compatibility. F01 uses protocol 13 because its new enum variants are rejected by older peers. The local host CLI probes compatibility before sending an authority request and reports an upgrade instruction without restarting the daemon. F01 does not add fields to every existing IPC envelope merely to reserve future shape. Each stage records mixed-version behavior, daemon/client installation order and fixture versions. Older clients must receive an actionable error rather than restart a remote host or fall back locally. Database migrations are additive; forward-fix after migration rather than assuming every older binary can open a newer schema. Migration 110 is a narrow exception: it only creates the two browser-session tables, and the migration runner ignores versions it does not know, so a 0.6.224 binary can still open that store. Check both the SQL and the runner before making the same claim for another migration. Portable backup/restore must invalidate remote auth while retaining workspace ownership/recovery safeguards.

F01 requests only `mail_read`; later write grants require explicit approval. Pairings expire after ten minutes, at most sixteen remain pending, and five failed claim proofs lock a request. Ordinary credentials expire after ninety days. Separate cleanup verifiers remain after expiry or revocation so lost-acknowledgement retries can only deregister the original client. Portable backup excludes all remote authority; restore clears it. Claude reviewed the complete foundation at `ab35c25c`; the orchestrator recorded the subsequent small corrections through `a8b79cf1`. [PR 443](https://github.com/planetaryescape/mxr/pull/443) merged as `974ec3d5`. The published macOS and Linux binaries each passed all 32 checks in [the isolated pairing fixture](remote-hosting/verify_pairing.py). Both platform checksums matched; Homebrew and a separate `install.sh` installation matched the Mac archive. The [release workflow](https://github.com/planetaryescape/mxr/actions/runs/38306908031) passed, including Homebrew installation. The public [pairing guide](https://mxr.sh/guides/pairing-authority/), CLI reference and automation contract passed browser checks on the production deployment of `974ec3d5`.
