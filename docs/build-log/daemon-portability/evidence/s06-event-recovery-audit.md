# Socket-only gaps bypass the existing refresh path

Source audit of `origin/main` at `2c55a735e2b013910cb7222211fa8d6156d6204c`. Fast/gpt-6-luna/high traced the paths; the parent checked the critical control flow. [Blob manifest](s06-event-recovery-audit-2c55a735.json) pins the inspected files. No test or browser reproduction ran. Recheck after deployed S02–S05 before implementing S06; this does not freeze their contracts.

## A healthy HTTP probe does not account for missed events

The socket client reconnects with bounded backoff, but its status contains connection state, timestamps and an error message, with no replay cursor or workspace generation. Opening a socket reports connected; it does not replay missed events. [Socket implementation](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/ws.ts#L15-L27).

A connected-to-disconnected transition starts a status probe. If HTTP still answers, daemon-down remains false. `markReachable` returns immediately in that state, and the socket's later connected state does not trigger the down-only recovery path. The existing `refetchAfterGap` call therefore does not run for this sequence. [Reachability and socket transitions](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/daemonAvailability.ts#L92-L129).

`EventsLagged` does invoke `refetchAfterGap`, which invalidates views except queries carrying `keepThroughGaps`. The daemon emits that marker for per-client broadcast lag or an unencodable event, rather than disconnected-stream replay. Reuse the existing refresh helper and dirty-compose exemption. [Event handler](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/hooks/useDaemonEventInvalidation.ts#L75-L82), [daemon event forwarding](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/crates/daemon/src/serve.rs#L410-L460), [refresh helper](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/daemonAvailability.ts#L137-L157).

Existing availability tests cover daemon outage/recovery and a socket drop when the daemon is actually down. Their setup does not cover an event-only gap while HTTP stays healthy. [Current tests](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/daemonAvailability.test.ts#L116-L153).

## A bridge URL is not a durable workspace identity

The admin response exposes PID, version, build and an instance label. The label comes from `MXR_INSTANCE` or the debug/release default, not persisted workspace identity. The local handshake returns a token and source. These contracts do not bind an editor to a durable workspace or recovery generation. [Admin status](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/crates/web/src/admin_handlers.rs#L9-L38), [instance label](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/crates/config/src/resolve.rs#L43-L62), [handshake](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/localHandshake.ts#L16-L43).

Remote-origin switching already requires confirmation during URL bootstrap. After confirmation, the bridge URL is kept in global localStorage and request URL resolution reads it. That consent must be preserved; it does not itself scope cached mail or draft state. [Remote bootstrap and URL storage](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/tokenStorage.ts#L10-L49), [URL resolution](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/tokenStorage.ts#L102-L115).

At this baseline the compose query key is intent-only and excludes gap refresh. The active-draft localStorage entry holds a host path, account and timestamp under an intent key, with no bridge or workspace identity. S02 changes this recovery code, so these lines are a historical seam to recheck rather than a ready patch target. [Compose query](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/features/compose/useComposeSession.ts#L63-L79), [active draft storage](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/features/compose/session/activeDrafts.ts#L12-L43).

## Existing queues prevent retries but do not establish target ownership

TanStack mutation retry is disabled and its network mode is always, avoiding a hidden offline replay queue. The separate compose coordinator serializes every queued task by key; it marks older returned results stale rather than skipping those tasks. `cancelAll` aborts replaceable requests only, not compose or mutation tails. An identity transition must account for those existing queues and editor buffers explicitly. [Query defaults](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/queryClient.ts#L54-L60), [coordinator](https://github.com/planetaryescape/mxr/blob/2c55a735e2b013910cb7222211fa8d6156d6204c/apps/web/src/lib/requestCoordinator.ts#L54-L107).

A future isolated journey should have two distinct legs. First keep HTTP healthy, drop only WebSocket delivery, change/delete sentinel mail through CLI, then reconnect and require fresh visible state while dirty text survives. Then use two fake profiles with the same build/protocol and disjoint data: confirm a target change while an editor or queued save belongs to the first profile, and require preserved text plus no old-workspace command submission to the second. Re-select the first profile and read its saved draft. No cross-host path collision or runtime outcome is claimed by this audit.
