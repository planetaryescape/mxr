## Findings considered and rejected (do not re-audit)

- **ipc.rs reconnect oneshot "race"**: each queued `IpcRequest` carries its own
  oneshot; late replies are skipped by the id check at `client.rs:52`
  (`resp_msg.id == id`). No misattribution path exists.
- **`ipc_call_dedicated` drops daemon events** (`ipc.rs:306-307`): by design —
  the daemon broadcasts events to every connection (`server.rs:244`); the main
  worker connection receives them. Nothing is lost.
- **Analytics stale-response leaves `loading = true`** (`runner.rs:2814-2822`):
  self-healing — every view switch sets `refresh_pending` which fires a fresh
  request whose response clears `loading` (`analytics_actions.rs:19-58`,
  `runner.rs:1511-1520`). No user-visible wedge.
- **`let _ = result_tx.send(..)` swallows send errors** (runner.rs, various):
  the receiver only drops at app shutdown; failures there are moot. Hygiene,
  not a bug.
- **Scroll-offset underflow ×3** (`mailbox_helpers.rs:698`,
  `daemon_events.rs:299`, `search_helpers.rs:440`): impossible — each
  `selected_index + 1 - h` is guarded by
  `selected_index >= scroll_offset + h` with `scroll_offset ≥ 0`, so the
  result is ≥ 1. False positive from a second-pass audit agent.
- **TUI attachment save-path traversal**: the destination is typed by the
  user, which is user intent, not attack surface; mail-controlled filenames
  are hardened daemon-side (commit `c0780377`). Defense-in-depth there would
  fight legitimate use.
