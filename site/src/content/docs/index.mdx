## try it

<p>These commands work after <code>mxr demo</code> or after you connect an account.</p>

```bash wrap
# search your whole mailbox from the local index
mxr search "from:supplier@example.com has:attachment after:2019"

# rank newsletters by how little you read them, then leave
mxr subscriptions --rank --format json
mxr unsubscribe newsletter@example.com --dry-run

# surface what you owe a reply to
mxr owed --since 7 --format json

# give an agent structured results
mxr search "from:sarah@example.com after:2026-04-23" --format json | jq '.results[0]'
```

<p class="tryit-contract">Most reads can return JSON. Core mail mutations support <code>{`--dry-run`}</code>, so scripts and agents can show their work before changing your mailbox. <a href="/examples/">Browse more examples →</a></p>

## read and search without a connection

<div class="spread">
  <div class="narrative">
    <h3>Your synced mail stays available.</h3>
    <p>Open mxr on a plane with the wifi off. Read a thread, search the archive, and write the replies you owe. Opening a message is a SQLite read, and a draft saves straight to disk. When you reconnect, mxr pulls in new mail and you can send the drafts you wrote offline.</p>
    <p>Years of messages and labels stay indexed locally. Attachment names, types, and sizes are part of the local record. mxr downloads an attachment into its cache when you open it.</p>

<div class="search-coda">
  <p>Find a 2019 contract by the supplier's name. Pull every receipt from a vendor. List the apology email you sent in March. mxr indexes subject, body, sender, and attachment filenames with <a href="https://github.com/quickwit-oss/tantivy">Tantivy</a>. Lexical search runs against the index on your disk, without a provider round trip or provider rate limit. Optional local embeddings add hybrid and semantic search.</p>

  <p>The same local record makes mailbox analytics cheap to run: storage by sender or attachment type, response times, stale threads, subscription activity, and a year-in-review.</p>

```bash wrap
mxr storage --by label --limit 20
mxr stale --mine --older-than-days 14
mxr wrapped
mxr search "subject:invoice" --format json | jq -r '.results[].from' | sort -u
```

## let your agent use the same inbox

<p>Search and mail reads stay on your computer. Once your mail is synced, a hosted model call is the only network wait in this workflow. The agent can use the CLI or the first-party MCP server to search, read, draft, summarize, export, and preview changes.</p>

<div class="agent-conversation">
  <div class="agent-turn">
    <div class="agent-label">◈ prompt</div>
    <div class="agent-prompt">Find the latest thread with Sarah. Look at how I normally write to her, then draft a short reply in the same tone. Do not send it.</div>
    <div class="agent-runs">
      <code>{`mxr search "from:sarah@example.com OR to:sarah@example.com" --format json`}</code>
      <code>{`mxr sender sarah@example.com --format json`}</code>
      <code>{`mxr draft-assist <thread-id> "short reply in my usual tone"`}</code>
    </div>
    <div class="agent-result">Relationship context and recent threads loaded ◈<span class="agent-ok">draft created, nothing sent.</span></div>
  </div>

  <div class="agent-turn">
    <div class="agent-label">◈ prompt</div>
    <div class="agent-prompt">Find every CI failure email from last week. Cross-reference with my recent commits and archive the ones whose tests have since been fixed.</div>
    <div class="agent-runs">
      <code>{`mxr search "from:ci@github.com after:2026-04-30" --format json | jq -r '.results[] | [.message_id, .subject] | @tsv'`}</code>
      <code>{`git log --since=1.week --pretty='%H %s'`}</code>
      <code>{`mxr search "from:ci@github.com after:2026-04-30 subject:upload" --format ids | mxr archive --yes`}</code>
    </div>
    <div class="agent-result">23 failures, 18 from the upload suite that a later commit fixed ◈<span class="agent-ok">18 archived, 5 left for review.</span></div>
  </div>
</div>

<p>The CLI, MCP server, web bridge, and TUI all call the same daemon. Most read commands can return JSON. Core mail mutations support <code>{`--dry-run`}</code>, and MCP mutation and send tools require <code>{`confirm=true`}</code>. <a href="/guides/automation-contract/">See the automation contract →</a></p>

## changes stay in sync

<p>mxr keeps a local copy and syncs changes in both directions. Read, label, and archive in another client; mxr picks up those changes. Make the same changes in mxr; your provider receives them.</p>

<div class="duplex-grid">
  <div class="duplex-side">
    <div class="duplex-side-label">◈ in your other client</div>
    <ul class="duplex-actions">
      <li><span class="duplex-arrow">→</span> read a thread in Gmail web on your phone</li>
      <li><span class="duplex-arrow">→</span> apply a label in Apple Mail</li>
      <li><span class="duplex-arrow">→</span> archive a newsletter from your watch</li>
    </ul>
  </div>
  <div class="duplex-bridge">
    <div class="duplex-mech">Gmail History API</div>
    <div class="duplex-mech-line">↕</div>
    <div class="duplex-mech">Outlook OAuth2<br/>+ IMAP / SMTP</div>
    <div class="duplex-mech-line">↕</div>
    <div class="duplex-mech">IMAP CONDSTORE<br/>+ IDLE</div>
  </div>
  <div class="duplex-side">
    <div class="duplex-side-label">◈ in mxr after sync</div>
    <ul class="duplex-actions">
      <li><span class="duplex-arrow">←</span> mxr sees the read state</li>
      <li><span class="duplex-arrow">←</span> the label appears in mxr's sidebar</li>
      <li><span class="duplex-arrow">←</span> the newsletter leaves the inbox</li>
    </ul>
  </div>
</div>

<p>Gmail, Outlook, and your IMAP server remain upstream. The synced local archive stays readable on your computer when the provider or network is unavailable.</p>

## daily mail tools

<div class="cap-grid">
  <div class="cap"><strong>Compose in $EDITOR.</strong> Write Markdown with your own keybindings and plugins. mxr builds and sends the multipart message.</div>
  <div class="cap"><strong>Reader mode.</strong> Remove tracking pixels, banners, signatures, and quoted text from the terminal view.</div>
  <div class="cap"><strong>Follow-up queues.</strong> Track replies you owe, remind yourself when someone has not replied, snooze threads, and schedule sends.</div>
  <div class="cap"><strong>Mailbox analytics.</strong> Inspect response times, stale relationships, subscription activity, and storage by sender or attachment type.</div>
  <div class="cap"><strong>Mail rules.</strong> Preview and run rules that label, archive, star, mark, or route matching mail.</div>
  <div class="cap"><strong>Saved searches.</strong> Keep useful mailbox queries in the TUI sidebar and rerun them without rebuilding the filter.</div>
