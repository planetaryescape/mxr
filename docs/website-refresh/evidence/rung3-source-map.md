## Current workflow map

The first screen for the human journey is Now, but Now is a chooser, not a sixth mode with its own completion action. The five modes use different primary objects and verbs. Their detailed guides already contain the implementation handoffs below; R3 can sharpen the entry and completion wording without inventing a workflow.

The daemon’s one `SetModeDone` plan feeds both preview and apply (`mode_done.rs#L14-L17`, `#L201-L208`). For a real apply it archives and marks read via `ReadAndArchive` only for the eligible live inbox messages, then stores per-mode marks and an operation-specific undo entry where possible (`mode_done.rs#L371-L413`, `#L416-L508`). Archive’s mode is explicitly excluded from done (`#L125-L128`). These semantics are more precise than “every mode’s done archives” or “all done actions are universally undoable.”

### Provider and offline boundaries for journey copy

- The mode archive effect is a provider mutation, not a local record filing: code calls the provider mutation path only after last-mode eligibility. Its default can be turned off (`crates/config/src/types.rs#L108-L121`; `crates/daemon/src/handler/mode_done.rs#L371-L437`). Describe it as conditional and previewed, not guaranteed for each action/provider state.
- The provider contract separates sync from sending and exposes per-account capabilities and mutation application (`crates/core/src/provider.rs#L8-L12`, `#L38-L65`, `#L141-L165`). The adapter maps provider behavior; do not add a generic compatibility matrix without checking the relevant provider’s actual capability/implementation.
- Offline claims should stay to synced local mail/search and saved local work; sync and provider mutations need connectivity, and uncached attachments need provider fetch. The First sync guide explains backfill/progress/local data (`site/src/content/docs/getting-started/first-sync.md#L14-L25`, `#L44-L57`). Remote mailbox explicitly requires the host to stay awake and online (`site/src/content/docs/guides/remote-mailbox.md#L6-L6`). Use those as the human-journey boundaries; don’t imply full offline attachments or remote access from anywhere.
