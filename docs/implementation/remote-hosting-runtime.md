# Remote hosting has previewed service setup and a per-boot admission boundary

Implementation worktree: `fix/remote-web-desktop-parity`, based on `origin/main` `f4ab9360a275f7917177c4fd5af7c91c557ce495`. These are implementation notes, not a release or installed supervisor acceptance receipt.

`commands/serve/hosting.rs` owns previewed setup/start/stop and TLS rejection checks. `supervisor.rs` renders user launchd/systemd services, checks their recorded content digest and refuses unrelated edits. `proxy.rs` compares the exact HTTPS port, hostname and sole root proxy; it never resets the full Serve configuration. `state.rs` writes private, fsynced desired state and reconciliation progress. `runner.rs` verifies offline workspace/recovery identity before starting a daemon and confirms authenticated local readiness before opening the gateway. Explicit profile and credential paths follow the service; a saved remote selection does not change its local owner.

`remote_lifecycle.rs` keeps one registry per `AppState`, with a fresh boot ID, 90-second leases, bounded session memory and a mutex that serializes drain with remote operation admission. A retained admission guard counts accepted remote work until its handler exits. Drain permits readiness, workspace identity, ping and send/archive/job outcome inspection, rejects new mail work, and leaves existing mail-operation recovery identities intact. `handler/remote.rs` authenticates every lease touch/close and closes matching leases after revocation or cleanup. Durable registration authority stays in the store; presence clears at a new boot.

`AppState::request_shutdown` enqueues `ServerStopping` before signaling shutdown. The IPC connection flushes queued events before it stops accepting requests. The gateway must forward the notice while idle and validate the current registration before forwarding any event. The browser/client reconnect handshake must observe fresh readiness and discard stale boot notices.

The CLI exposes `serve setup`, `serve start`, `serve stop`, `serve stop --all` and `daemon stop`, with preview default and `--confirm` for mutations. `serve status` reports authority, registrations and leased presence. `serve stop` persists stopped hosting intent before service/proxy cleanup and leaves local sync running. A full stop also disables daemon recovery; ordinary autostart refuses to reverse it. An explicit daemon start clears only daemon intent. Raw legacy IPC `Shutdown` remains the existing maintenance primitive, because restart also uses it; persistent operator stop goes through the CLI commands.

The source-level fixtures cover lease expiry and boot changes, admission/drain ordering, independent client sessions, proof rejection and revocation, private stopped-state persistence, proxy ownership conflicts, service escaping and read-only rejection of paused/replaced offline owners. The parent delivery owner records exact final test commands and results after the candidate stops changing. A stale `cargo check -p mxr --tests` run (queue task 1490) was cancelled after source changes invalidated its candidate; it is not a successful check. Its only emitted integration error was a missing `session_json` field in a root-owned CLI test pattern, reported to the parent.

No live launchd/systemd installation, proxy mutation, reboot, real mailbox migration or persistent VPS deployment was performed. Tailscale Serve syntax was checked against its official CLI documentation: `--bg --https=<port> <target>` installs a persistent mapping, and `--https=<port> off` removes that port. The local read-only Serve status showed unrelated existing mappings; they were left untouched.

Final isolated browser acceptance remains pending in the parent handover. The service review checked the installed Apple `launchctl(1)` and `launchd.plist(5)` manuals. `kickstart` without `-k` starts a loaded stopped job without killing a running instance; `bootout` removes its definition. launchd kills descendants sharing a job's process group, so the daemon child uses its own process group, matching the existing daemon detachment pattern. Linux uses `KillMode=process` for the same hosting-only stop boundary. The runner invokes the recorded absolute mxr executable and explicit profile/token/secrets paths; it never invokes Tailscale or an interactive shell.

Primary-source checks on 2026-11-05 used the [Tailscale Serve CLI reference](https://tailscale.com/docs/reference/tailscale-cli/serve), [ServeConfig source](https://github.com/tailscale/tailscale/blob/main/ipn/serve.go), [Serve CLI implementation](https://github.com/tailscale/tailscale/blob/main/cmd/tailscale/cli/serve_v2.go), [certificate-domain status contract](https://github.com/tailscale/tailscale/blob/main/ipn/ipnstate/ipnstate.go), [systemd quoting rules](https://www.freedesktop.org/software/systemd/man/latest/systemd.syntax.html), [ExecStart substitution](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html) and [Environment assignment rules](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html). The proxy checks background and foreground port conflicts and refuses a Funnel-enabled chosen origin. It requires the selected hostname in `CertDomains` before applying setup. `off` targets background configuration without needing `--bg`; no global reset is used. ExecStart escapes dollar signs, while Environment preserves them literally; both escape backslashes, quotes and percent specifiers.


A saved-selection generation change now retires the immutable native client target before it opens another connector. The target rechecks after its readiness handshake as well. A long-lived MCP requester therefore fails explicitly on its next call instead of contacting its previous host. CLI event following already propagates `next_event`'s selection error and exits. The TUI closes its old worker and pending request queue, enters a sticky `SelectionChanged` state and asks the user to reopen; late readiness and retry actions cannot revive it. Its private draft text and original workspace owner remain intact. Reopening starts a fresh app and resolves the deliberate new selection; the old session never adopts it.

Regression fixtures added in `crates/tui/src/selected_daemon_tests.rs`: `changed_saved_selection_retires_idle_worker_and_blocks_old_mcp_target` uses a real isolated Unix socket and checks socket closure, no second connection, no old-host business request, and rejected dedicated/MCP calls after the generation changes. `retired_selection_keeps_private_owner_and_cannot_be_revived_by_late_readiness` keeps unsent text and its original owner while rejecting late connected/retry transitions. Both passed in the final scoped TUI run (13 selected tests, `/tmp/mxr-pool3-final-scoped-rust-tests-20261106-r2.log`).


Autostart now reads a shared version-1 desired-state projection in `mxr-config`: a missing hosting record permits normal local autostart, an explicitly disabled daemon blocks it, and invalid/missing fields or unknown versions fail closed. The helper changes neither file contents nor permissions. All client-spawned daemon children carry `MXR_DAEMON_CLIENT_AUTOSTART`; they recheck stopped intent and never run the explicit operator-start hook. TUI spawning uses `MXR_INSTANCE` and `MXR_SOCKET_PATH` rather than the unsupported `daemon --instance` arguments.

Desired-state writes and a tagged daemon's final startup boundary use a separate file gate. A daemon checks again after potentially slow `AppState` initialization and holds the gate through listener/provider-worker admission, then releases it before serving. An operator stop committed while initialization was running therefore prevents the late child from starting provider work. Tagged running daemons also watch later stopped intent. The gate is not held for the daemon lifetime. Fixtures cover read-only projection behavior, invalid state, serialized stop-before-start and TUI reconnection refusing autostart without a live personal daemon.

Draining readiness is explicit: `RemoteReady.accepting_mail` defaults false and the handler supplies its current value plus shutdown deadline. A recovered connection can inspect its original accepted outcome without being mistaken for revoked credentials. New mail operations receive retryable `remote_host_stopping`; workspace verification and readiness remain usable. Native connections queue the matching boot's stopping notice when they authenticate to a draining host, and deliver it before ordinary event reads. The parent delivery owner records final compile/runtime results; these source changes do not add a claim of installed Mac/Linux supervisor acceptance.

Disabled desired state no longer makes the supervisor abandon its gateway before notification. Its monitor joins the same boot's bounded drain while the gateway remains polled. Concurrent drains keep the first shutdown deadline; an empty in-flight set still leaves idle clients their notice window. A tagged daemon also keeps its accept loop available for status and outcome recovery until that deadline. Full stop captures the local daemon's reported PID and process start identity, then confirms the original owner has exited and no daemon socket remains reachable. A lost final drain or shutdown reply does not turn that confirmed stop into an error; an unresponsive live owner is not reported as stopped.

Local and public gateway health checks now require the exact socket-derived profile ID as well as service and protocol. Another profile occupying the same listen port cannot satisfy setup. The profile-collision and shared-deadline fixtures are in `crates/daemon/src/commands/serve/hosting/tests.rs`. Real supervised setup/reboot evidence remains pending the parent delivery owner's final acceptance environment.
